# 261028-1126 — Safe ordinary-file import
**Goal:** Close a data-integrity gap in the old Catalog-only Add files flow and enable browser-first file-backed capture.
**Decision:** Ordinary files must remain ordinary filesystem files. No auto-suffix collision renaming, no Catalog-only resources, no unverified success.
**Implementation:** Shared import planner (filename, size, batch limits), destination case-insensitive enumeration, per-file SHA-256 source/readback verification, fail-closed partial error. Replace old unverified import with explicit native file input and drag/drop review, current Folder or chosen Folder, and user confirmation. Keep existing URL/text .url/.md capture; add casefold collision guard there too. Service worker precaches the importer.
**Testing:** Automated Node tests exercise source integrity, collisions, unsafe names, size limits, unsupported providers, simulated write/readback corruption and partial writes. PR CI must be observed before merging; no physical Windows or Pixel 8 test, no screenshots.
**Limitations:** Browser File System Access has no O_EXCL; last-moment empty-file race and provider bugs remain. 25 MiB/file and 50 MiB/batch intentionally constrain memory; large-file streaming is future work. Android picker may select but cannot promise a writable destination. Partial writes require manual inspection; Syncthing and device acceptance M0 remain open.
