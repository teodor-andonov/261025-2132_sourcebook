# 2026-10-27 — V0.0.5 compact tag pills

## Decision

Focus on tags before introducing custom properties. Keep the app grayscale with a single blue focus/selection accent; no extra inspector controls. Nested slash paths are temporary resource labels; the pre-existing stable-ID taxonomy helpers are preserved and should be wired to persistence in a later slice.

## Delivered

- `src/tags.mjs`: pure validation, slash-delimited provisional paths, case-insensitive deduplication and 64-tag cap; no filesystem calls.
- `src/app.mjs`: add/remove hashtag pills via keyboard and ×, commit pending input on Save, preserve notes and existing record schema; reject a record created concurrently after selection.
- `src/styles.css`: grayscale surfaces and file placeholders, compact inspector, neutral pills; accent picker deferred.
- `sw.js`: cache version bumped and tag module included for offline shell.
- `tests/tags.test.mjs`: path, Unicode, duplicate, invalid-input, limits and legacy-label tests.
- `scripts/capture-desktop.mjs`: real Chromium fixture now exercises pill creation/removal and persistence; synthetic source files only.

## Validation and limitations

- Check Node CI after commit; screenshot gallery updates only after nightly/manual Chromium workflow. No claim of fresh screenshots until run succeeds.
- Not full hierarchical tags: stable-ID taxonomy helpers exist but no `tags.json` persistence wiring, reparent/merge UI, descendant filtering UI, bulk tagging or custom property schema yet.
- No physical Windows/Pixel 8 validation. GitHub Pages remains blocked pending Settings → Pages → GitHub Actions.

## Concurrent development reconciliation

Another development cycle had already added stable-ID tag taxonomy helpers and tests immediately before this change. Restored and retained those helpers and their original tests; added the pill-input helpers as exports to the same module, with separate editor tests. The UI now normalizes slash paths consistently with the taxonomy's spaced separator. No history was rewritten.

## CI follow-up

The restored upstream taxonomy test used a constant ID factory for a two-level tag path, correctly triggering the module's duplicate-ID guard. Updated that fixture to allocate unique IDs and reference the leaf ID. The implementation's collision protection is unchanged.
